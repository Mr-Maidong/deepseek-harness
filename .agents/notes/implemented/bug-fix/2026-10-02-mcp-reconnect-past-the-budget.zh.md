# Agent Note: MCP 重连越过尝试预算后继续

Status: implemented

[English](2026-10-02-mcp-reconnect-past-the-budget.md) | 中文

## Problem

两种连接丢失会让 MCP 服务在插件重载或 Host 重启之前一直不可用。连续失败达到 `maxAttempts` 后，监督器停止重连并注销该服务的工具，因此崩溃后又恢复的本地服务再也无法被重新接入。服务端断开的 Streamable HTTP 会话会保持传输对象打开，只通过 MCP 客户端的错误回调报告丢失，而监督器忽略该回调，因此已死服务的工具仍处于注册状态，此后每次调用都失败，直到进程结束。第三种情况正好相反：stdio 子进程的传输始终无法确认关闭时，监督器会停止重连并打印要求重载的日志，用一个卡住的进程换来了永久不可用的服务。

## Decision

客户端的 `onerror` 与 `onclose` 一起作为丢失信号。每一代只做一次丢失决策：该处理只在已建立的代（`attemptSettled` 且已记录 `connectedAt`）上生效，把重复报告合并为一次重连，并把连接阶段的报告留给该次尝试自己的失败路径。stdio 仍通过 close 上报，而 HTTP 会话现在有了一条不必等待其传输从不发送的信号的路径。

耗尽尝试预算时只注销一次该服务的工具，并继续以 `maxDelayMs` 探测，而不是停止。注销被排入串行化所有注册替换的同一条 sync 链，因此不会与进行中的重新同步竞争；之后成功的代会同时清除注销标记和尝试计数，从而重新注册工具。由于预算不再终止这次中断，恢复的服务无需人工操作即可使用；日志会说明重试仍在以该上限继续。

传输始终无法确认关闭的代将成为重连循环的持有者。它的关闭屏障保存在 `stuckClose` 中，每次调度的中断 tick 都会在创建替代连接之前重新检查该屏障；只要屏障报告传输仍然存活，该 tick 就进入下一次延迟，而不是新建连接。清理也通过同一屏障关闭，因此生命周期长于其传输的服务进程既不会被替代连接重叠，也会在卸载时被关闭。关闭世代时会先释放它开启的 Streamable HTTP 会话（[会话释放 Agent Note](2026-10-02-mcp-http-session-release.zh.md)）。

清理现在会在正确的位置终止循环：一旦已清理，`scheduleReconnect` 不再安装定时器，`connectGeneration` 也拒绝再创建代，因此比卸载更长寿的 tick 不会创建无人关闭的对象。

## Alternatives considered

**继续在预算处停止并让用户重载。** 这是此前的行为。它假定有人会看到那行日志、且服务失败是永久性的，这对常见的本地服务崩溃并不成立：进程会恢复，而只有一次无关的重载才能让它的工具回来。

**通过探测来发现已死的 HTTP 会话。** 周期性请求会增加流量，需要自己的超时策略，并把请求级重试与连接所有权混在一起。MCP SDK 已经在受影响的请求上暴露传输失败，监督器现在消费的正是这个信号。因此，能接受请求但从不回应的连接仍然不会被发现；[包 README](../../../../packages/mcp/mcp-client/README.zh.md) 把它记录为限制而不是承诺。

**对每个错误报告都重连。** 一次中断会报告多次失败——每个失败的请求和每次 SSE 重试各一次——每次都会启动一代。每代一次丢失的守卫保证一次中断只有一个持有者。

**去掉卡住的关闭屏障并强制替换。** 替代连接会在传输尚未确认死亡的进程旁边再启动一个服务进程，而这正是该屏障要防止的重叠。

## Consequences

中断耗尽预算后，只要它持续存在，就会每 `maxDelayMs` 探测一次；定时器保持 unref，因此探测本身不会让进程保持运行。永不恢复的服务不会保留任何已注册工具，原先要求重载的日志现在改为报告该上限延迟。丢失检测依赖 SDK 报告传输失败，因此静默停滞的连接仍然无法被发现。

验证：`packages/mcp/mcp-client/tests/reconnect.spec.ts` 覆盖已建立的 HTTP 代通过错误报告丢失、达到上限后继续探测并只注销一次工具、未确认的关闭屏障推迟替代连接，以及持屏障的 tick 待处理期间发生清理。`packages/mcp/mcp-client/tests/negotiation-lifecycle.spec.ts` 覆盖没有 close 信号时从传输错误报告恢复，以及被推迟的替代连接。它们验证的当前重连策略记录在 [MCP 客户端插件说明](../feature/2026-07-07-mcp-client-plugin.zh.md)和[包 README](../../../../packages/mcp/mcp-client/README.zh.md)中。
