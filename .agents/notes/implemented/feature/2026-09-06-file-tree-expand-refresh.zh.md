# Agent Note：文件树展开文件夹时重新读取

Status: implemented

[English](2026-09-06-file-tree-expand-refresh.md) | 中文

## 问题

Studio 文件树把一个目录只读取一次，并在这次面板生命周期内一直复用结果，所以在文件夹保持展开期间——或者在它折叠但路径仍留在持久化展开集合里期间——由 agent 新建、修改、删除的文件既不会出现也不会消失。用户想看到当前内容，只能切换工作区或者刷新页面。

## 决策

在 `packages/client/ui-studio` 里，文件夹展开时重新读取，并把这次读取当作唯一的失效触发器：

- 路径不在上一次渲染的展开集合里，或者没有缓存的目录列表，就读取。工作区 store 会持久化 `expandedPaths`，因此经历“折叠—再展开”一轮的文件夹算一次新的展开，会被重新读取。
- 展开一个文件夹时，它下面所有仍处于展开状态的路径一并重读，于是折叠过的子树恢复出来的是文件系统此刻的内容，而不是折叠之前的。
- 每个路径同时最多只有一次未完成的读取：已经有一次在飞时就丢弃新的请求，所以工作区根的初次加载与首轮展开不会把它读两次。
- 读取失败时保留屏幕上已有的目录内容。只有工作区根拥有面板级失败态（`无法读取此目录`），因为只有它的缺失会让面板无从渲染。
- 每次读取都走与初次加载相同的 `listDirectory(path, signal)` seam，且只有展开这一个触发器：没有定时器，也没有会话回合钩子。

## 后果

- 展开一个文件夹就是一次目录读取；折叠再展开就是用户的刷新动作，因此不需要额外的刷新控件、缓存 TTL 或过期标记。
- 读取落定就重渲染文件树，于是被反复展开的文件夹会被反复读取。跨展开不做任何缓存，这正是本次改动的目的。
- 磁盘内容变化时始终保持展开的文件夹仍不会被重读：浏览 seam 没有 watch，只有展开能了结过期。
- 根行以请求时的工作区路径为键，而不是 Host 回传的规范化路径，因此旧构建写下的持久化展开条目可能让根保持折叠，直到用户手动展开一次。

## 考虑过的替代方案

- **在文件树标题栏加一个刷新按钮。** 否决：展开文件夹本就是用户已经在做的动作，再加一个控件需要自己的位置、文案和可用态，表达的却更少。
- **由 Host 监听目录并推送变更。** 延后：浏览 seam 没有订阅；watch 需要先确定自身生命周期、打开路径上限和失效词汇表，才谈得上取代用户主动发起的读取。
- **折叠时把后代路径从 store 中移除。** 否决：那会抹掉用户搭建的布局，而且重开时子树依旧过期。
