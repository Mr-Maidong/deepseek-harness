# Agent Note: Studio 预览行号与引用行高亮

Status: implemented

[English](2026-09-10-studio-preview-line-numbers.md) | 中文

## 问题

万能预览卡片把工作区文件显示为一整段没有行号的文本。从工作区搜索进入的读者看到卡片滚动到了命中的行，却没有任何行引用可看，而搜索跳转闪烁整块界面，并没有标出具体哪一行。想引用某一行时，读者必须精确拖选文本才能弹出“引入”气泡：既看不到气泡将要插入哪些行，指向单独一行也需要精细的拖拽。

## 决策

卡片的 code 模式在源码旁渲染行号 gutter，行号承担两种必要的高亮。

- 每个源码行一行，由 `preview.content.split('\n')` 生成。gutter 是滚动界面的第一个子元素（`pre.code` 是 `span.gutter` 与 `code.text` 组成的 flex 行），因此两列共用同一个滚动盒子和界面的 22px 行高，行号与各行自然对齐，无需测量文本。gutter 使用 `position: sticky; left: 0`，横向滚动长行时会滑到固定列下面。`user-select: none` 和 `aria-hidden` 保证行号不进入选区、复制内容和无障碍树。
- 搜索跳转命中的行（`preview.focus.line`，按已打开文件裁剪）在该预览打开期间保持行号高亮，取代了整块界面闪烁。滚动效果现在按命中行自身的矩形与界面测量，不再假设像素行高。
- 气泡引用的行会高亮对应行号，因此即将以 `@"path" Lx-Ly` 插入的范围在卡片上可见。
- 点击行号即引用该行：先清空浏览器选区，使被标记的行号和气泡成为“引用哪一行”的唯一依据，插入结果为单行 `Lx-Lx`。点击代码文本则不会影响已弹出的气泡。

只有 ready 的 code 状态带 gutter：读取中、读取失败和内嵌产物都没有可编号的源码行。

`StudioPreview` 的 ready 状态现在按 `kind` 区分——`{ kind: 'code', content, language?, focus? }` 与 `{ kind: 'iframe', content }`——不再是一个成员携带 `StudioPreviewKind`。行号代码需要 ready 源码状态作为类型（在 `kind` 不是字面量时 `Extract<StudioPreview, { status: 'ready'; kind: 'code' }>` 为 `never`），而拆分也如实表达语言标签与跳转行只属于源码。

## 备选方案

**每个代码行一个元素，用 CSS 计数器或每行 span 编号。** 否决：code 元素必须始终只包含文件文本，因为选区到行范围的换算按它的 `textContent` 字符偏移计算，且复制选区不能带上数字。逐行代码体还会在每次选区变化时重渲染所有行。

**在文本列上绘制高亮条。** 否决：文件文本是一个节点，行内高亮条要么需要逐行元素，要么需要按行高常量定位的绝对定位浮层，而卡片的半透明面板会让滚动中的文本透过浮层显形。

**在行号高亮之外保留临时的整块界面闪烁。** 否决：闪烁没有标出任何一行，还要用定时器给 `<pre>` 增删 CSS Modules 类；行号高亮是渲染状态，并在预览打开期间持续可见。

**给所有预览模式加行号。** 否决：内嵌产物渲染的是文档而不是行，读取中与失败状态则没有内容。

## 后果

- 搜索跳转变得可定位：卡片把命中行滚到中间，并保持其行号高亮，直到被另一个预览替换。
- 引用单行不再需要精确拖拽。拖选与点击行号两条路径显示同样的高亮行号，并共用同一个气泡。
- gutter 在有界读取（1 MiB）内按源码行数占用元素，因此超大文件会渲染相应更大的 gutter。
- 行号是展示性的，不进入选区和无障碍技术；键盘路径仍然是文本选区加气泡按钮。

## 测试

`tests/file-tree-preview.client.spec.tsx` 覆盖 ready code 的 gutter、读取中/失败/iframe 状态下没有 gutter、裁剪后的搜索命中标记、拖选引用的行范围、点击行号引用（清空浏览器选区、标记行号、插入单行引用）、落点不在行号上的点击，以及不产生引用的各条路径。
