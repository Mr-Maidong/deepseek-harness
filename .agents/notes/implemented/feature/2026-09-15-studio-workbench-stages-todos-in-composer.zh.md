# Agent Note：工作台把事项暂存到输入框，而不是发送

Status: implemented

[English](2026-09-15-studio-workbench-stages-todos-in-composer.md) | 中文

## 问题

工作台的发送控件调用 `session.prompt([{ type: 'text', text: message }], 'queue')`，因此一次点击就把消息派发给模型，并在同一手势里把卡片置为 `in_progress`。用户在消息运行前没有机会阅读、删减或补充它，而卡片还宣称了一次用户可能根本不想要的派发。

## 决定

暂存把事项的标题、id 与详情写入当前 Session 的输入框草稿，发送交给用户。通道来自输入框自身的 session 作用域标准份额——`useInput` 读取实时草稿，`inputActions.setDraft` 写入——因此不涉及新的 import 或 inject 面。暂存拼接在输入框已有草稿之后，因为一次点击不应悄悄销毁用户输入的内容。既然没有任何内容抵达模型，发送路径不再改动事项状态，也不再携带失败分支；卡片保持原有状态。写回仍然直接发送到聊天，因为该动作的目的就是让模型作答，而两个暂存控件的文案点名了输入框。

## 考虑过的替代方案

- **暂存时仍把事项标记为 `in_progress`。** 已否决：卡片会宣称模型正在处理一个其实只是躺在输入框里的条目。
- **覆盖草稿而不是追加。** 已否决：一次点击就会丢弃用户进行中的草稿，而 `setDraft` 的替换语义是为写入已持久化的草稿而存在，不是为合并暂存文本。
- **把写回也走输入框。** 已否决：写回的存在意义就是让模型写回总结，暂存它会让一个本已是明确请求的动作变成还需要用户再手动发送一次。
- **为输入框新增一个工作台专用的 inject。** 无必要：`inputActions` 是 session 作用域的标准份额，该 slot 本就已收到它。

## 后果

- 暂存的消息仍携带模型调用 `workbench_complete` 时必须回显的 todoId 标题，用户可以在发送前编辑文本。
- `updateTodoStatus` 现在没有生产调用方。它被保留，因为已持久化的工作区存储仍可能保存卡片会渲染的 `in_progress` 与 `blocked` 事项。
- 发送控件在工作台 spec 中覆盖了空草稿、非空草稿、仅空白草稿与「发送全部」四种情形，另有一例钉住写回仍然直接发送。
