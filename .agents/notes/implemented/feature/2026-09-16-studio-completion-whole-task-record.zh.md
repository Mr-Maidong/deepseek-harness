# Agent Note：工作台完成记录覆盖整份任务

Status: implemented

[English](2026-09-16-studio-completion-whole-task-record.md) | 中文

## 问题

灵光工作台为每个工作项保留一份完成记录，而 `workbench_complete` 每次调用都会替换它：`studioTodoCompletions` 投影按 `todoId` last-wins 折叠，工作区 store 也允许模型写回覆盖已完成事项（注释即 "iterative refinement across turns"）。面向模型的契约对此只字未提。描述只要求回显 `todoId`、说明完成时机、只报告实际运行过的验证命令；`summary` 被描述为 "User-facing result summary"；写回请求则把范围框成「本次执行」。因此对同一工作项的后续修正会触发第二次调用，其摘要只描述那次修正，并静默替换掉第一次调用写下的整份记录。本次事故中记录的列表恰好仍是超集，所以只检查列表并不能拦住它：丢失发生在正文。

## 决定

整份任务的规则由工具自身的契约与写路径承担，因为工具描述是唯一在每次调用时都处于模型上下文中的指令：

- `workbench_complete` 的描述写明：对同一 `todoId` 的后续调用会替换先前的记录，因此摘要、实现路径、修改文件与验证必须覆盖任务做过的全部内容——每一项需求以及之后的每一次修正——而不是只写最新一次改动。`summary`、`implementationPath`、`changedFiles`、`verification` 的参数描述重复了整份任务的覆盖范围。
- `execute` 在 append 之前读取调用会话自己的 `studioTodoCompletions` 投影。该事项已有记录时，若替换丢掉了任一已记录的 `changedFiles.path` 或 `verification.command`，调用会在任何内容落到日志之前抛出。拒绝信息列出被丢掉的条目，并回显被替换的记录——它的完成时间与摘要——以便模型合并后再次调用。实现步骤属于正文，不做比较。
- 被接受的替换返回 `replaced: true` 以及被替换记录的时间与摘要；其渲染结果说明记录覆盖整份任务，并在摘要或任一列表只描述最新一次改动时，要求模型带完整记录再次调用。
- 工作台的写回请求要求整份记录——从开始到现在的完整成果，含后续追加的修正。

修改文件路径与验证命令是任务做过什么的事实，因此这条单调规则就是记录的语义，而不是启发式：任务改过之后又回退的文件仍然属于该记录。

## 考虑过的替代方案

- **保留每一份被替换的记录并在卡片中列出。** 本次未采纳：需要把 `studioTodoCompletions` 投影改成追加式列表（`stateVersion` 递增）、增加客户端 store 字段与新的卡片区域。该投影日后可以改成这种形态，而不必触碰写路径。
- **把投影折叠成一份合并记录**（摘要拼接、列表合并）。未采纳：卡片会显示按时间拼接的补丁而非一份可读的摘要，而且与「要求模型重写整份记录」的契约相冲突。
- **对摘要文本做校验**（长度、子串或语义检查）。未采纳：正文的完整性没有机械判据，长度也不是证据——本次事故中的增量摘要与被它替换的记录差不多长。
- **每个工作项只允许写一次。** 未采纳：store 刻意允许模型再次写回，以便修正后的任务重写记录；拒绝第二次调用会把第一版错误记录冻结下来。
- **只改写回请求的措辞。** 未采纳：该提示只出现在卡片按钮上，而工具描述随模型的每次调用一起出现。

## 后果

- 记录是整份任务的日志：替换会保留任务此后回退过的文件与已被取代的命令。描述写明了这一点，因此被拒绝是预期输入，而不是意外。
- 替换的调用结果会完整回显被替换的摘要，因此比之前单行的结果更长。
- 守卫只读取调用会话的投影。另一个会话为同一 `todoId` 写下的完成记录不参与比较，这与投影和工作台把记录绑定到其产出会话的方式一致。
- 未改动 Session 事件载荷、投影 wire 值、`SESSION_FORMAT_VERSION` 与客户端数据结构。
- `packages/todo/tool-todo/src/index.ts` 此前没有覆盖 `workbench_complete` 的 spec（按文件的分支覆盖率为 67.85%）；新 spec 补齐了这一缺口。

## 测试

`packages/todo/tool-todo/tests/workbench-complete.spec.ts` 通过 `ctx.tools.execute` 驱动真实插件，钉住：首次调用 append 已 trim 的整份任务完成记录及其渲染文本，`todoId` 与 `summary` 仅含空白的拒绝，非 agent 调用者的拒绝，保留先前每个文件与命令的替换被接受（投影以 last-wins 暴露该替换），丢掉已记录文件路径的替换被拒绝且不 append，丢掉已记录验证命令的替换被拒绝，注册的 schema 携带替换语义句子，以及稳定的呈现调用。该文件达到语句、分支、函数与行 100% 覆盖。

`packages/client/ui-studio/tests/workbench.client.spec.tsx` 钉住写回请求在携带事项标题与 id 的同时要求完整记录。
