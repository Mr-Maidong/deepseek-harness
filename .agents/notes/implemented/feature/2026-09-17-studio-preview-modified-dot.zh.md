# Agent Note：预览卡片用文件名前的圆点表示文件已改动

Status: implemented

[English](2026-09-17-studio-preview-modified-dot.md) | 中文

## 问题

编辑卡片的标题行里，语言标签与关闭控件之间原本是一个带边框的文字控件，显示 `保存` 与 `保存中…`。它说的是动作，状态则要靠用户自己察觉禁用/启用的翻转才能得知缓冲区是否仍与文件不一致；而且在这条只放安静字形图标的标题行里，一个带边框的按钮显得突兀。

## 决定

标题行把文件状态画成一个实心圆点，紧贴在文件名之前，与卡片其他字形图标复用同一套手绘 `Icon` 包装：

- `ModifiedDotIcon` 是一个 `currentColor` 实心圆。`PreviewCard.module.css` 让它的容器在缓冲区与文件一致时为 `var(--studio-muted)`，不一致时为 `var(--studio-gold)`，以 `data-modified` 为准。
- 该元素仍是 `<button>`：可访问名（`preview.save`）、提示（`preview.saveHint`，写入进行中为 `preview.saving`）、缓冲区干净或写入进行中时的 `disabled` 状态、以及点击保存的行为都保持不变。改变的是画法与位置，而不是能力：指针仍然保有编辑器本已提供的保存，禁用状态也仍然表示无处可保存。
- 圆点的渲染条件与原先的控件相同——代码预览、存在编辑面、缓冲区已载入——因此只读卡片与渲染产物卡片都不显示圆点。

## 考虑过的替代方案

- **把圆点做成纯装饰**（`<span aria-hidden>`），只保留 `Ctrl+S` 保存。未采纳：这会在未被要求的情况下移除指针保存，而颜色将成为唯一信号，其后没有任何可访问名。
- **保留文字控件再加圆点。** 未采纳：同一事实对应两个控件，而需求是把按钮替换掉。
- **用 class 而非 `data-modified` 决定颜色。** 未采纳：工作台卡片已把状态发布为 data 属性，用 class 拼接会把被着色的状态藏起来。
- **新增文案说明状态**（`未保存` 标签或提示）。本次暂缓：本次改动不新增词条，提示与禁用/启用状态已使控件语义不变；若单靠颜色过于含蓄，为状态命名就是下一步的自然做法。

## 后果

- 卡片标题行现在只有字形图标，圆点沿用标题行 12px 的间距排在文件名之前。
- 写入进行中圆点保持金色，因为缓冲区在写入落定前仍与文件不一致；提示会说明当前步骤，被拒绝或失败的写入同样保持金色，并在卡片下方显示失败提示条。
- 未改动文案、词条、Session 事件、样式 token 或 wire 值；`preview.save`、`preview.saveHint`、`preview.saving` 在两个字典中都保留。
- jsdom 不应用样式表，因此 spec 钉住的是状态属性与 DOM 顺序，而不是计算出的颜色。

## 测试

`packages/client/ui-studio/tests/preview-edit.client.spec.tsx` 新增一例：该控件内含圆点的 circle、紧排在文件名之前、静止时报告缓冲区与文件一致、编辑后报告为已改动、从圆点保存后重新报告为一致。写入进行中的用例现在断言圆点保持已改动（金色）、提示为保存中且处于禁用；既有用例继续钉住干净缓冲区的禁用状态，以及只读卡片与渲染产物卡片上不存在该控件。
