# Agent Note：工作室待办列表在仍可滚动的一端渐隐

Status: implemented

[English](2026-09-17-studio-todo-list-end-fades.md) | 中文

## 问题

工作台待办列表在工作室面板内滚动，而面板会裁切它：上边缘被面板自身的控件覆盖，下边缘紧接添加事项的表单。高于剩余视口高度的卡片会在两端被从中间截断，且没有任何迹象表明其后还有卡片，于是列表看起来就到此为止。会话正文与聊天轮次导航都用可滚动端的渐变遮罩解决这个问题；该列表此前没有。

## 决定

列表在每个仍可滚动的一端用最后 16px 做遮罩：

- `Workbench.module.css` 新增 `fadeTop` 与 `fadeBottom` 遮罩及二者合并规则，采用与聊天轮次导航相同的 `mask-image` 渐变写法。遮罩跟随滚动容器自身的边缘，因此不需要覆盖元素、不需要层叠顺序、也不需要颜色 token。
- `workbench.tsx` 依据列表的 `scrollTop`、`scrollHeight` 与 `clientHeight` 读取两端，容差 1px；每次渲染后重读——新增、展开或收起卡片都会在没有滚动事件的情况下移动溢出边界——并在滚动与 `ResizeObserver` 盒尺寸变化时重读。其后已无内容的一端不做遮罩，因此只有一张卡片时它保持全不透明。
- 16px 是该列表自己的带宽：正文遮罩 24px、被裁切的文件路径 28px，而这些卡片之间本就留有 10px 间距。

## 考虑过的替代方案

- **无条件遮罩两端。** 未采纳：短于滚动视口的列表会把第一张卡片顶部与最后一张卡片底部洗淡，而工作台通常刚打开时事项很少。
- **用覆盖元素而非遮罩做渐隐**（`::before`/`::after` 叠加到面板背景色的渐变）。未采纳：它需要把面板背景作为 token，在卡片之上增加一个可能拦截指针事件的图层，并且背景改变时会失效。
- **只在滚动时重读两端。** 未采纳：展开卡片或新增事项会在没有滚动事件的情况下改变溢出，渐隐会滞后于用户刚造成的布局。
- **复用聊天轮次导航的滚动状态辅助函数。** 不可行：它内置于 `ui-chat`，而特性插件不得从该包的展示目录引入值。

## 后果

- 遮罩同样覆盖列表细滚动条的末端，其滑块会在两端 16px 内渐隐。
- 只有某一端发生变化时渐隐才移动；两端位置未变的滚动不会触发重渲染。
- jsdom 既不做布局也不实现遮罩，因此 spec 钉住的是选择遮罩的类状态，而不是实际渲染出的渐变。
- 没有新增面向用户的文案、词条、Session 事件或 wire 值；未新增样式 token。

## 测试

工作台 spec 的 `StudioWorkbench todo list end fades` 块钉住：内容未超出滚动视口时没有渐隐；长列表顶部只有底部渐隐；列表中部两端都有渐隐；最后一屏只有顶部渐隐；重复滚动且两端未变时类名不变；盒尺寸变化时观察器重读并在卸载时断开；以及没有活动项目的渲染——此时没有列表可渐隐。
